# Hermes 原生技能清理兼容性修复

本次修复基于插件 `784a772`，适配 Hermes v2026.8.19（源码提交
`fcbd1076a93841fa88855acce810e342a5b78101`）。只修复原生技能清理被
`workspace_delete_guard` 误判为工作目录外删除的问题。记忆反例误判不在本次范围。

## 行为变化

之前，`skill_manage(action="delete"/"remove_file")` 被转换成通用 `delete`。
当技能库位于当前工作目录之外时，即使技能及文件都合法，插件也会拦截。

现在，仅对宿主确认的原生技能清理，解除这一项“工作目录外删除”限制。
其他防护及 Hermes 自身的权限、技能所有权、固定技能、先读后写、合并要求继续执行。
后台合并删除仍走 Hermes 原生归档，前台删除保留宿主原有语义。

不是整个技能库的删除白名单。终端 `rm`、内联脚本、通用删除工具、自定义替代工具、
找不到的技能、无法确认的路径都没有这个例外。路径不能是工作目录、其祖先、
profile 根目录、技能库根目录或受保护资源，也不能通过删除父目录连带删除保护对象。

## 路径及信任来源

- Python 适配器每次从当前 Hermes profile 的 `_find_skill`、`get_all_skills_dirs`
  获取实际技能位置和技能库。支持分类目录、自定义 `HERMES_HOME`、已配置的绝对或
  相对外部技能库，以及合法的技能库挂载链接；不硬编码用户名或部署目录。
- 复用宿主 `_validate_delete_target`、`_validate_file_path`、`_resolve_skill_target`
  校验。原生工具被其他插件覆盖时，不授予例外。
- 证据通过 Python/Node 私有桥接的顶层字段传递，独立于模型工具参数。宿主标识由
  适配器绑定。证据只用于当前调用，不在 session/global 状态中复用。
- Node 复核真实路径、技能归属和保护对象。Python/Node 文件系统视图不一致、链接
  越界、证据不完整时，沿用原有规则，不猜测路径映射。
- 后台归档还检查宿主实际归档目录，包含符号链接和受保护路径。因为宿主遇重名会
  追加时间戳，例外会保守检查整个归档命名空间；该区域被配置为保护对象时不放行。
- 这仍是执行前静态检查，保留现有宿主隔离边界，不承诺文件系统操作与检查原子化。

## OpenClaw 和性能

共享 `workspace_delete_guard` 及 `rules.ts` 保持原样。仅 Hermes 注册包装策略；
OpenClaw 不注册它，也不接受 Hermes 清理证据。提示词、注入位置、配置默认值不变。

新的路径验证仅用于两种原生技能清理动作。复用已有技能查找，不新增网络、模型调用
或后台扫描。其他工具调用不进行这项路径验证。例外应用记录在现有防护结果日志中，
该记录表示范围检查通过，不代表工具已经执行成功。

### 独立的 Hermes 宿主问题

v2026.8.19 的 `agent/relay_tools.py` 使用 `callback_context.copy().run(...)`
执行单次工具；`skill_view` 写入的 ContextVar 读取标记没有带回下一次工具调用。
因此，在该 AIAgent 调用链中，即使已经读取，后续 patch/remove_file 仍可能被
Hermes 的 `_read_before_write_required` 拒绝。

这个结果在停用 AgentAegis 的对照中也已复现。本次未修改 Hermes 源码、关闭原生
检查或人为补入读取标记；不能把它描述成“完整后台自进化全流程已通过”。
同一 review context 下的原生 registry 流程已经验证先读后清理成功，插件的误拦截
已解除；宿主上下文传播问题需要另行修复。

OpenClaw 原生回归使用真实宿主 dispatcher、执行包装器及 exec/write 工具；危险
Gateway 动作用执行哨兵验证未进入执行。初次测试目录名同时含 `skill` 与
`openclaw` 时触发既有 compact-command 误报，已对照确认旧插件同样命中；改用中性
目录名后完成回归。本次未修改这条既有规则。
