## 发现与修复

### 已移除的技能扫描接口

原版本 `40a50c6` 引用了 `agent.skill_utils.get_scan_ordered_skills_dirs`。
新版插件加载器在 2026-09-14 后拒绝加载使用该旧接口的插件，导致首次运行
33 项集成测试全部在插件加载环节失败。

改为组合两版均支持的 `get_project_skills_dirs()` 与 `get_all_skills_dirs()`，
保留项目、profile、外部目录的扫描顺序，并采用新版目录解析器提供的技能创建目录。
新增实际临时配置/文件测试，验证外部技能被扫描，项目技能仅在项目受信任时加入。
新版 `hermes plugins compat` 检查通过，无废弃导入；未启用 `allow_deprecated_imports`。

### 并发钩子被宿主跳过

接口修复后，32 项原测试通过，16 会话并发测试失败。新版默认的 30 秒钩子机制
以回调身份记录运行状态：同一个回调仍在执行时，另一个会话的调用会被跳过。
`pre_tool_call` 被跳过时宿主拒绝工具，其他钩子则可能直接略过，包括输入检测和结果脱敏。
这在回调没有超时的情况下也会发生。

新版必须配置：

```yaml
plugins:
  hook_callback_timeout: 0
  enabled:
    - agent-aegis
```

请合并进已有配置并重启。插件会检查宿主实际采用的超时配置；不满足条件时不启动
正常安全引擎，保留工具拒绝钩子并返回具体配置提示，避免静默降级。
没有修改宿主调度器或自动覆盖用户配置。

此设置关闭**整个 profile 中 Python 插件钩子**的宿主超时机制。
AgentAegis 自身仍串行处理请求，对每次 Node 写入/读取设置超时，并保留帧大小限制、
故障拒绝和进程回收；其他插件需要自行处理超时。适配器的串行排队不是整个宿主的
统一耗时上限。旧版没有该宿主机制，不强制要求此配置。

| 旧版 HTTP 指令位置回归 | 11 项断言通过 | 相同脚本，原始适配目标 |

原生矩阵重跑了命令开关、混淆、受保护路径的读写/补丁/链接/移动/删除、工作区外删除、
内联代码路径、配置/技能/插件自保护、多文件补丁、记忆单条/批量/直接文件/长度限制、
写后执行溯源、循环、进程故障、外泄链及关闭防护对照、结果注入/长度限制、
Base64/Base32/hex/URL/双重编码检测。所有操作仅使用一次性文件、无害标记或回环接收端。

矩阵的 `checks` 表示断言成立；真实文件/网络事实在 `actual`。
例如外泄场景的 `checks.sink_received=true` 表示“应未收到数据”的断言通过，
实际 `actual.sink_received=false`。不将观察项或模型主动拒绝算作插件拦截。

## KV cache 指令位置

新版实际发送的 5 个 `/v1/messages` 请求中：

- system JSON 均为 **8,113 UTF-8 字节**，逐字节一致。
- 工具定义 JSON 均为 **5,118 字节**，逐字节一致。
- 固定 AgentAegis 策略存在于 system；变化的技能风险指令不在任何 system 中。
- 动态技能风险进入当前用户消息；真实 `read_file` 的风险上下文立即附到新工具结果。
- 历史用户消息和工具结果重放时内容保持一致。

旧版修复后复测同样全部通过：system 为 8,492 字节，工具定义为 6,401 字节。
这些长度包含本次临时目录等环境信息，不作为固定值断言；验证的是同一会话各次请求
之间的字节关系。两版宿主原始提示词不同，因此不要求跨版本字节一致。
测试固定使用合成凭据，不保存请求认证头；没有测量供应商的缓存命中率。
