## 先读这段

我们要为 Agent Aegis 增加独立的 DWS 自动回复风险检查，补充识别绕过现有代回复助手的两类流程：

1. 同一次 Agent 运行中（三个指定宿主均纳入），取得外部钉钉消息，经后续模型处理，再直接向来源会话发送。
2. 一个简单脚本内，外部消息进入模型请求，模型返回的正文随后进入 DWS 发送命令。

**最高优先级是正常使用与用户体验。只拦截证据充分、实现可控的路径；不确定、复杂、超限的情形跳过新增检查，原有安全防护继续执行。** 不承诺完整封堵，不承诺 95% 覆盖率。

用户已明确：员工自己配置的固定模板可以自动发送；AI 生成或改写的答复应由员工审批。现有代回复助手已经负责审批，本次不改它，也不再建一套审批流程。

### 当前受支持的核心入口

- 明确的 DWS argv、单目标、文本正文和显式 `corp:user` profile；同一次运行内成功查询 `auth status`，并从真实人员结果取得本人 open ID。缺失身份或环境覆盖时不强行关联。
- OpenClaw 规则一使用原生 PI 工具循环中**紧接读取批次的下一轮模型结果**。要求普通 legacy 上下文、清理策略保留最近 assistant、没有自定义上下文限额/组装、模型上下文至少 32K token、所观察的来源结果不超过 8,000 字节；上下文压缩、重试、并发歧义、通知缺失均跳过。原生 Codex 运行时未提供同等证据时也跳过；不能将 PI 验证扩大为任意运行时覆盖。
- Hermes 规则一核对实际 `pre_api_request` 内的工具 ID 和来源行摘要，再关联原生 `post_api_request` 的工具调用 ID。正文被替换而只保留 ID 的情形不能命中。
- 规则二使用有界 Python AST，支持明确的 DWS 子进程、JSON/NDJSON 输入、已识别的 Requests/urllib/OpenAI/Anthropic 请求和返回正文流。执行参数覆盖、请求正文覆盖、自定义传输、复杂控制流及动态命令属于不支持范围。固定正文及模板 ID 选择不建立模型正文发送边。
- 监听管道的静态 NDJSON 字段已有支持；后台句柄经 `process` 返回的运行链尚不作为已支持入口。完整支持表以需求文档及最终报告为准。

## 2. 为什么需要这次补强

现有代回复助手通过专用监听任务、限制拟稿工具能力、草稿确认及受控发送保护自身流程。它没有承诺接管员工 Pod 内所有自行编写的脚本或其他 Agent 的 DWS 操作。

用户曾提供一个后台监听管道：DWS 监听消息后交给 Python 脚本回复“已知悉”。后来用户澄清该脚本只发送固定文本，运行时没有经过 Agent/LLM。因此，**“监听 + 自动发送”本身不是本次拦截条件**，不能继续沿用早期的一律禁止监听方案。

真正关注的是外部消息进入有数据和工具访问能力的 Agent/LLM，再绕过员工确认直接回复。这里的“普通 Agent”是指通过普通工具链处理任务的运行，不限于某个 agentId，也不特指 main 之外的其他 Agent。

我们把新增检查放在安全插件中，保持业务与安全职责清晰：

| 组件 | 职责 |
|---|---|
| 社区钉钉插件 | 钉钉 Channel、消息和卡片交互 |
| 现有代回复助手 | 监听偏好、主题识别、固定模板、AI 草稿、员工审批及受控发送 |
| Agent Aegis 新规则 | 对绕过助手、且经过可观察工具入口的明确风险流程进行补充检查 |

## 3. 部署背景

公司使用 Kubernetes，OpenClaw 约 15,000 个实例，一名员工一个 Pod、一个独立实例，未额外开启工具 sandbox。用户另确认 Hermes v2026.8.19 也采用一名员工一个 Pod/独立实例，钉钉私有化 IM 直连 Hermes，Web 经自研 Agent Gateway 接入。本节为产品背景。

主要入口：

- 钉钉私有化 IM → 社区版钉钉插件 → 员工 OpenClaw。
- 自研 Web → OpenAI 兼容 HTTP 接口 → 自研 Agent Gateway → 员工 OpenClaw。

以前使用官方 `dingtalk-openclaw-connector`，现在已经更换为社区版；后续不要按旧架构分析。

公司还有 OpenClaw cron 和 PowerJob 调度，但用户最终决定本次不专门考虑调度器。不新增调度识别、豁免或拦截规则；用户正文里的“本消息由【定时任务调度器自动触发执行】”不是可信授权。

公司此前说明线上使用最新版、未修改的上游 Agent Aegis。**这不代表线上已经安装用户的个人改造分支。** 本地验证记录实际宿主 commit、配置与 Node 版本。

## 4. 已定下来的边界

必须保留：

- 两条规则同时作为本次交付范围，独立于助手的监听开关。
- 只检查已适配的命令、事件和简单脚本语法；不能用关键词共现代替完整判断。
- 同一工具调用继续接受现有 Aegis、宿主及其他插件的防护；新增规则没有强制放行权限。
- 没有证据、无法解析、资源超限或检查异常时跳过本项检查，并记录原因。
- 只保留有限、短期的运行元数据；不落盘聊天正文、完整脚本、凭据或员工请求。
- 不增加驻留进程、网络服务、模型调用或热路径 DWS 身份查询。

明确不做：

- 不修改代回复助手、社区钉钉插件、卡片模板、DWS、OpenClaw/Hermes 核心、自研 Gateway 或 PowerJob；Aegis 自身的 Hermes 适配代码属于改造范围。
- 不把所有监听、所有读取或所有发送一律拦截。
- 不以 `--yes` 是否存在作为风险条件。
- 不增加统一发送服务、脚本提交审批 API、脚本迁移要求或新的审批卡。
- 不递归追踪多层脚本、模块、动态 eval、任意 HTTP 调用或任意跨运行数据流。
- 不根据 agentId、sessionKey 前缀、路径、提示词标记或工具参数中的 approved 给予免检。
- 不为了测试通过关闭 Aegis 原有策略。

阻断时仅返回：**“检测到外部消息经 AI 处理后直接自动回复，请通过代回复助手处理。”** 不自动替员工发消息，也不自动创建助手草稿。

4. 实现有界命令解析、运行记录和简单脚本数据链；先满足反误拦用例，再扩大已验证语法。

## 9. 尚待工程核实的问题

| 未知项 | 处理原则 |
|---|---|
| Hermes 脚本链真实证据 | 已正式纳入开发；补齐受支持脚本完整链路，不用一次模型拒绝推导无风险 |
| 模型调用与工具计划关联 | 三个指定宿主均必测，不可靠路径不阻断；“难以观测”不是“没有风险” |
| Hermes 原生 bridge 的异步结果与序列化等待 | 基线公共处理器同步返回；新增异步检查后 bridge 需 await 最终结果并映射拒绝，同时测锁等待与超时 |
| 本地宿主入口的可信本人请求与目标、正文提取 | 不信正文身份声明；没有可靠依据则跳过相关检查 |
| 未显式 --profile 的 DWS 身份 | 不能每次启动 DWS 查询，也不能假定不变；验证低成本证明方法，否则缩小覆盖 |
| 本地测试模型 HTTP 响应的具体结构 | 已知模式才适配；未知 HTTP 不猜成模型 |
| 本机 Node/Python 版本、文件读取与日志成本 | 按真实本地配置测量 |
| 监听原生命令实际形态 | 以实际 CLI 帮助和样本确定，不凭名称猜测 |

这些是技术验收门槛，不是要求新增平台改造。若核心路径无法在现有宿主信息下可靠实现，应清楚报告证据与缺口，不悄悄扩大误拦范围，也不把部分覆盖写成完整交付。
