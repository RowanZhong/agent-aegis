# 两类外围规则：性能与 Agent Aegis 共存评估

日期：2026-09-27。当前结论是设计评估与隔离回放，不是新规则已完成实现或公司 Pod 真机验收。

## 已确认的基线

用户确认公司使用最新公开 Agent Aegis、无公司代码修改。通过 GitHub API 核对当日 main 为 23d59b8986b86de448d24ff973e662295768d533，package.json 为 2026.3.14。不能只用包版本判断，因为本地另有相同包版本的修改分支 7137092；本次没有使用该分支进行兼容性测试。公司具体防护配置和 Pod CPU/内存配额尚未提供，回放采用上游默认 enforce 配置。

测试使用从该 Git commit 导出的真实 index.js/src/*.js，以及本地 OpenClaw 2026.7.1-2、2026.8.1 的真实 hook runner。执行位置为临时隔离目录；未启动 Gateway，未执行工具命令、DWS、模型或外部网络请求，也未更改任何业务仓库、公司配置、运行中的助手或 Aegis。工具事件为合成输入，额外插件只是用于验证组合语义的允许/拒绝/空处理测试探针，不是拟开发的外围规则。

环境：Apple M5，arm64，10 个逻辑 CPU，24 GiB 内存，macOS，Node v26.8.1。日志使用计数输出端，包含 Aegis 构造及序列化日志字符串的成本，不包含生产 stdout、磁盘和日志采集成本。未触发 Gateway 启动技能扫描；文件读取为操作系统缓存命中的重复读取。

## 实测基础耗时

| 项目 | 样本数 | P50 ms | P95 ms | P99 ms |
|---|---:|---:|---:|---:|
| 旧版真实宿主 + 空 before_tool_call 探针 | 2000 | 0.00825 | 0.02217 | 0.04942 |
| 旧版真实宿主 + Aegis + 空探针，普通 DWS 发送形态 | 2000 | 0.05346 | 0.07067 | 0.14196 |
| 新版真实宿主 + 空 before_tool_call 探针 | 2000 | 0.00254 | 0.00504 | 0.00921 |
| 新版真实宿主 + Aegis + 空探针，普通 DWS 发送形态 | 2000 | 0.04842 | 0.06363 | 0.09587 |
| 已有 DWS 发送命令解析器 | 10000 | 0.00121 | 0.00163 | 0.00217 |
| 只异步读取 8 KiB 文件，缓存命中 | 1000 | 0.02042 | 0.03017 | 0.05213 |
| 只异步读取 64 KiB 文件，缓存命中 | 1000 | 0.01617 | 0.02792 | 0.05417 |

这些数值证明基础操作在本机较轻，但没有包含新运行关联、完整脚本语法解析、生产调用分布、Pod 限流或存储尾延迟。不能把它们相加当作完整检查 P95，不能声称新规则只增加 0.1 ms，也不能从 P95 相减得到严格的增量延迟分布。正式比较应在同一负载下测 Aegis-only 与 Aegis+真实新规则的成对分布和端到端结果。

Aegis 普通工具检查在本次无 debug 的计数 logger 中每次生成约 33 条日志调用、约 7.6 KB 日志字符串；实际采集取决于宿主日志级别。这是现有 Aegis 基线成本，不归因于新规则。15000 Pod 部署需要纳入日志吞吐，不能只测正则扫描耗时。

1 万次 Aegis 检查并清理后，GC 后 heapUsed 从 7713552 到 7905544 字节，RSS 从 101859328 到 108003328 字节。该短测仅观察 Aegis/V8，包含堆扩容等影响；不是新规则的内存数据、泄漏判定或容器容量预测。

## 共存回放结果

两版结果一致：
- 普通 DWS 消息查询、两种发送写法、监听启动、简化后台监听管道、普通 Python 文件入口在默认 Aegis 下通过。
- Aegis 允许时，另一个 before_tool_call 探针可拒绝，前后两种优先级都不能被 Aegis 的允许覆盖。
- Aegis 拒绝时，后续探针不执行；探针先允许也不能覆盖 Aegis 后来的拒绝。
- 同 session/run 的完全相同 dws chat message list 连续执行四次，前三次通过，第四次因 loop_guard 拒绝。阈值为 3，计数还受 run/session 生命周期和 TTL 影响。这不代表所有 cron、每条新任务或不同参数的查询都会被拦。
- openclaw status 被 Aegis 的命令策略拒绝。只是合成工具输入，没有执行 CLI。
- 简单脚本写入记录测试中的 Python 列表形式调用 openclaw 没有被识别阻断；不能将 Aegis 的“脚本来源防护”解释为任意脚本都已覆盖。

## 单独确认的 Aegis 宿主适配问题

上游 wrapHookFailOpen 无条件返回 async 函数，并用于 before_message_write。两版宿主都要求该 hook 同步返回。合成敏感输出样本中，直接处理器返回了修改后的 message，但通过真实注册与宿主调用时结果为 undefined，并出现“returned a Promise; this hook is synchronous and the result was ignored”警告。

因此该路径的消息修改返回结果被忽略，不能依赖它完成持久化前的改写/脱敏；处理器其他同步副作用仍可能发生，不能推导全部 Aegis 防护失效。before_tool_call 的拒绝回放正常。本问题不是新规则造成，本轮没有修复或发布 Aegis。新规则不依赖 Aegis 已完成脱敏，也不尝试恢复被其他有效策略剔除的数据。

## 对 R4 方案的具体约束

我们保持双方策略独立。建议新增外围 before_tool_call 使用 -100，晚于上游 Aegis 默认 0；Aegis 已拒绝的操作无需再读取脚本。现有助手策略优先级保持原样。新增检查仅返回 undefined 或明确 block，不返回强制允许，不改工具参数，不覆盖审批，不自动重试规避拒绝。任何一方拒绝都不得执行。

运行观测只记录实际成功返回的消息，before_tool_call 仅登记候选。Aegis 在更早环节拒绝、结果丢失、宿主通知拥塞/延后等情况不能凭候选记录推断模型看过消息。双方状态分离；不根据 Aegis 改写的系统提示、提示词标记或风险标签授予本人授权。Aegis 的其他策略仍可阻断操作；本次“正常使用不受影响”应准确理解为新增规则不额外误拦，而不是豁免 Aegis。

新插件使用进程内文件 API 读取候选脚本，不再通过 Agent exec/read 工具发起二次检查，避免递归触发两个 hook 或污染 Aegis 的重复调用计数。已知新版本支持工具 matcher，可仅注册 exec/process 等实际支持入口；旧版本使用兼容的工具名早返回。不能假定新增全局 hook 零成本：新版宿主会隔离复制 before_tool_call 参数，大参数工具应验证 matcher 过滤是否成功。

不新增常驻进程、模型请求、DWS 身份查询、全目录扫描或同步日志落盘。文件异步读取，解析在进程内有界执行；单入口最多 64 KiB，节点数/步骤数有上限。不用单个 Promise.race 伪装成能中断同步 CPU 解析；在解析步骤中检查预算，I/O 超时取消或忽略迟到结果。建议 50 ms 为内部软等待预算，超过则跳过本项检查，不能等到宿主 hook 的秒级超时。CPU throttling/事件循环阻塞可能导致真实墙钟超过软预算，必须实测。

## 建议验收预算（目标，不是已达到结果）

| 路径 | 新增检查 P95 目标 |
|---|---:|
| 无关工具/无候选上下文 | ≤ 1 ms |
| 普通直接 DWS 链路判断 | ≤ 2 ms |
| 单入口脚本 ≤ 8 KiB | ≤ 10 ms |
| 单入口脚本 8–64 KiB | ≤ 30 ms |

这些目标要在公司同配额 Pod、固定工作负载中验证；当前缺少 CPU requests/limits、内存配额和存储类型，不能把本机数据按固定倍数转换。每次检查会串行增加到对应工具调用之前，多次工具检查会累计；独立会话虽不因异步文件等待被互斥锁住，仍共享 Node 事件循环和 CPU。

新增常驻进程目标为 0；新增稳态存活堆数据预算先按 ≤ 2 MiB/Pod 设计（含规则状态/缓存，模块与解析器贡献一并测量），RSS、启动峰值和 GC 独立测量，不能用堆预算宣称 RSS 上限。15000 Pod 若各常驻增加 2 MiB，则合计约 29.3 GiB，避免大缓存。缓存和活动 run 均有数量/大小/TTL 上限，满额跳过而不产生无界队列。

## 正式性能与兼容性验收

在真实新规则完成后，使用同样模型、固定消息与脚本集、同样 Aegis 配置、日志级别、Node 版本和 Pod 配额，比较：
A. 现有助手 + Aegis；
B. 现有助手 + Aegis + 外围规则。

同时覆盖两版宿主、钉钉/Web、自定义脚本和只读查询、本人原文发送、助手卡片审批与固定模板自动回复；错误、超时、并发顺序、大参数、文件冷缓存和慢挂载卷也纳入。测端到端响应、每次检查 P50/P95/P99、CPU-ms、cpu.stat throttled、事件循环延迟、RSS/heap、日志量和后台清理。保留单 Pod 平稳/突发与多 Pod 同步启动压力；至少持续 24 小时资源与状态回收观察。

先将任何误拦归属到 Aegis、新规则或宿主，不自动关闭/降级 Aegis。新规则不达预算时缩小受支持语法/输入范围或优化，不用忽略宿主超时换取表面成功。未完成上述联合真机和性能验收前，只能报告“组合语义已回放、核心规则待验证”。
